# DNA Bioinformatics Analyzer

[![Algorithm](https://img.shields.io/badge/Algorithm-DNA%20%2F%20ORF-blue)](#алгоритмы-и-сложность)
[![Status](https://img.shields.io/badge/Status-Completed-brightgreen)](#)
[![License](https://img.shields.io/badge/License-MIT-yellow.svg)](#лицензия)

Консольный анализатор нуклеотидной последовательности, написанный на Go. Программа читает FASTA-файл, выполняет простую очистку последовательности и находит открытую рамку считывания (ORF), после чего рассчитывает нуклеотидный состав и выполняет базовые преобразования ДНК → мРНК → белок.

Обработка реализована непосредственно в памяти с использованием стандартной библиотеки Go: ввод читается построчно, последовательность собирается через `strings.Builder`, а поиск ORF и подсчёт состава выполняются линейными проходами. Это обеспечивает небольшой runtime-overhead и предсказуемые затраты ресурсов на последовательностях разумного размера. Текущий проект — учебный прототип, а не универсальный FASTA-парсер или клинический инструмент.

## Пайплайн обработки

```text
gfp_bloated.fasta
        │
        ▼
  bufio.Scanner ── пропуск заголовков и пустых строк
        │
        ▼
  strings.Builder ── объединение строк, приведение к верхнему регистру
        │
        ▼
  Поиск и удаление точного мотива GGGGGGCCCCCC
        │
        ▼
  Поиск первого ATG и стоп-кодона (TAA / TAG / TGA)
        │
        ├── Подсчёт A/T/C/G и GC-состава
        ├── Построение обратной комплементарной цепи
        ├── Транскрипция ДНК в мРНК
        ├── Трансляция мРНК по таблице генетического кода
        └── Печать результатов в stdout (ANSI-цвета)
```

## Возможности

- Чтение многострочной последовательности FASTA: заголовки `>` и пустые строки пропускаются, символы последовательности приводятся к верхнему регистру.
- Вывод предупреждений о символах, отличных от A/T/C/G. Такие символы отмечаются, но сохраняются во входной последовательности.
- Удаление всех вхождений заданного мотива `GGGGGGCCCCCC` до поиска ORF.
- Поиск первой открытой рамки считывания в прямой цепи: первый найденный `ATG`, затем первый стоп-кодон `TAA`, `TAG` или `TGA` в той же рамке.
- Вывод координат ORF (нумерация с 1), длины и последовательности; стоп-кодон входит в возвращаемую ORF.
- Подсчёт количества A, T, C и G и расчёт GC-состава среди распознанных нуклеотидов:

  $$GC\% = \frac{G + C}{A + T + C + G} \times 100$$

- Построение обратной комплементарной последовательности ДНК.
- Транскрипция заменой T на U.
- Трансляция кодонов мРНК в однобуквенные обозначения аминокислот по таблице генетического кода; перевод останавливается на стоп-кодоне.
- Форматирование аминокислотной последовательности и базовая проверка того, что белок начинается с метионина (`M`).
- Демонстрационная функция «сплайсинга»: оставляет заглавные латинские буквы и отбрасывает остальные символы. В текущем запуске она обрабатывает встроенную тестовую строку, а не входной FASTA.
- Ограничение отображаемых последовательностей до первых 60 нуклеотидов.

## Требования

- Go 1.22.2 использовался для проверки сборки; минимальная поддерживаемая версия явно не задана.
- Внешние зависимости отсутствуют — используются только пакеты стандартной библиотеки Go (`bufio`, `fmt`, `os`, `strings`).
- Запуск выполняется из каталога проекта: приложение ожидает файл `gfp_bloated.fasta` в текущем рабочем каталоге.

## Установка, сборка и запуск

Откройте каталог клонированного репозитория:

```bash
cd dna-bio-analyzer
```

В репозитории пока нет `go.mod`; поскольку программа состоит из одного Go-файла и использует только стандартную библиотеку, её можно собрать напрямую:

```bash
go build -o dna-bio-analyzer main.go
```

Запуск собранной программы:

```bash
./dna-bio-analyzer
```

Либо запустите без сохранения отдельного бинарного файла:

```bash
go run main.go
```

Запускайте команды из корня репозитория, где расположен `gfp_bloated.fasta`. Сейчас путь к нему задан в исходном коде, поэтому позиционные аргументы и CLI-флаги не поддерживаются. Файлы `gfp.fasta` и `sample.fasta` в текущей версии автоматически не читаются.

### Формат входных данных

Входной файл — FASTA; заголовок начинается с `>`, за ним может следовать одна или несколько строк нуклеотидной последовательности. Пример структуры:

```text
>sequence description
ATG...
...TAA
```

Для анализа другой последовательности в текущей версии поместите её в `gfp_bloated.fasta` либо измените путь, заданный в `main.go`.

## Технологический стек

| Компонент | Применение |
| --- | --- |
| Go | Реализация алгоритмов и CLI |
| `bufio.Scanner` | Построчное чтение FASTA |
| `strings.Builder` | Сборка последовательности и форматирование белка |
| `map[string]string` | Таблица кодонов мРНК |
| Стандартная библиотека | Файловый ввод, строки и вывод в консоль |

## Алгоритмы и сложность

Обозначения: $N$ — длина нуклеотидной последовательности, $P$ — количество кодонов, обработанных при трансляции.

| Операция | Время | Дополнительная память | Примечания |
| --- | --- | --- | --- |
| Чтение FASTA и сборка строки | $O(N)$ | $O(N)$ | Память содержит собранную последовательность; Scanner читает построчно. |
| Поиск/удаление заданного мотива | $O(N)$ | $O(N)$ | Создаётся новая строка; заменяются все точные вхождения. |
| Поиск ORF | $O(N)$ | $O(N)$ | Линейный проход; возвращается копия найденного фрагмента. |
| Подсчёт состава и GC | $O(N)$ | $O(N)$ | В текущей реализации `strings.ToUpper` создаёт строку для подсчёта. |
| Обратная комплементарная цепь | $O(N)$ | $O(N)$ | Используется временный срез рун и результирующая строка. |
| Транскрипция | $O(N)$ | $O(N)$ | Две последовательные строковые замены. |
| Трансляция | $O(P^2)$ в худшем случае | $O(P)$ | Конкатенация результата через `+=` может копировать накопленную строку на каждом шаге; lookup кодона в map ожидаемо $O(1)$. |
| Форматирование белка | $O(P)$ | $O(P)$ | Для построения строки используется `strings.Builder`. |

## Ограничения текущей реализации

- ORF ищется только в прямой цепи и только в одной рамке, связанной с первым найденным `ATG`; обратная цепь и альтернативные рамки не анализируются.
- Если у первого найденного старт-кодона нет стоп-кодона в его рамке, функция завершает поиск и не проверяет последующие `ATG`.
- Координаты ORF относятся к последовательности после удаления мотива, а не к исходному FASTA.
- Символы вне A/T/C/G выводятся как предупреждения, но не отфильтровываются; подсчёт GC их игнорирует.
- `bufio.Scanner` использует стандартный лимит размера токена (строки); очень длинная строка FASTA может вызвать ошибку чтения.
- Нет параметров CLI для выбора файла, настройки мотива или переключения алгоритмов.
- Трансляция использует повторную конкатенацию строк; для больших последовательностей её стоит заменить на `strings.Builder`.
- Проверка белка подтверждает только наличие `M` в начале и не является биологической валидацией последовательности.
